# 安全与漏洞披露

*版本 {{doc.version}}，最后更新于 {{doc.updated}}。*

我们高度重视安全，欢迎研究人员出于善意提交报告。联系方式：**[{{company.email}}](mailto:{{company.email}})**。

## 1. 范围 {#scope}

范围内：{{product.name}}、{{company.website}}，以及我们运营的自有子域名、应用程序和 API。**范围外：** 第三方服务和基础设施、其他客户的账户和数据、针对我们员工或用户的社会工程学攻击或钓鱼、物理攻击、拒绝服务和大流量测试、垃圾信息，以及需要不切实际的用户交互或使用过时软件才能发生的问题。

## 2. 测试规则 {#rules}

如果您善意地进行测试，您必须：

- 仅针对**您自己的账户和数据**进行测试；如果您接触到他人的数据，应立即停止并予以报告，并且不得为证明问题而访问、下载、修改或保留超出必要范围的内容；
- 不得损害服务、不得进行大流量的自动化扫描，也不得利用漏洞持续控制、横向移动或窃取数据；
- 在我们有合理时间进行修复之前（自您报告之日起**90 天**，或经我们同意的更早时间），不得向他人披露该问题或公布其细节；
- 遵守法律和本规则。

## 3. 安全港 {#safe-harbour}

如果您遵守本政策，我们将视您的研究为经授权的行为，不会因此对您提起或支持法律诉讼，也不会因此终止您的账户，并将与您合作以理解和解决问题。这并不授权您违法侵害第三方的权益，第三方仍可能自行采取行动。如有疑问，请先向我们咨询。

## 4. 应提交的内容 {#report}

请提供对漏洞的清晰描述、受影响的 URL 或组件、复现步骤或概念验证、影响范围、您的联系方式，以及您是否希望获得署名致谢。如果可能，请对敏感材料进行加密；如需我们的密钥，请向我们索取。

## 5. 后续流程 {#process}

我们会确认收到报告、进行分级处理、向您持续通报进展，并根据严重程度进行修复；如果您愿意，我们会对您予以致谢。我们目前不设付费漏洞赏金计划，因此无法承诺提供奖励，但我们可能会向您表示感谢或赠送纪念品。

## 6. 用户：保护您的账户 {#users}

请使用唯一且强度高的密码，并在提供的情况下启用多因素身份验证，保持软件更新，提防钓鱼行为，并在怀疑账户遭到入侵时及时发送邮件至 [{{company.email}}](mailto:{{company.email}}) 报告。滥用漏洞或在本政策范围之外进行测试，构成违反[可接受使用政策]({{url.acceptable_use}})的行为。
