# Instructions for AI coding agents: rapttor/legal

Versioned legal page TEMPLATES (Markdown + placeholders), a placeholder catalog, a licence catalogue with a tag-based advisor, translations, and a small PHP reference implementation (`Library`, `Renderer`, `Advisor`, `Transliterator`). Distributed as a Composer package; other languages (npm, PyPI) must pass the same fixtures. Read this file before changing anything. Rules for using the pages in an app are in the wrapper's AGENTS.md (`rapttor/yii2-legal`) and in [SPEC.md](SPEC.md).

You are not a lawyer. Do not claim any text here guarantees compliance. Never put real company data in the templates: everything site-specific is a placeholder.

## What lives where

| Path | What | Edit by hand? |
|---|---|---|
| `en/<doc>.md` | English source texts | yes |
| `<lang>/<doc>.md` | Translations (`sr`, `hr`, `bs`, `cnr`, ...) | follow `i18n/TRANSLATING.md` |
| `placeholders.json` | every key, label, `required`, `default`, `flag`, `block` | yes |
| `presets.json` | country presets, product profiles (feature bundles) | yes |
| `i18n/` | `languages.json`, `jurisdictions.json`, `glossary.json`, `keep-latin.txt`, `TRANSLATING.md`, `BRIEF-<lang>.md` | yes |
| `licenses/` | `catalog.json` (tags), `advisor.json` (questions/rules), `texts/`, `i18n/`, `GUIDE.md` | yes |
| `manifest.json` | generated index | **never**: run `php tools/build.php` |
| `src/`, `tools/`, `tests/` | PHP reference implementation, CLIs, fixtures | yes, with tests |

## After EVERY change

```bash
php tools/build.php     # lint all templates, translations, catalogue; regenerates manifest.json
php tests/run.php       # grammar fixtures, advisor, transliteration, every language x every feature flag
```
Both must be clean. `php tools/build.php --lint` checks without writing the manifest. Commit `manifest.json` with the change.

## Template rules

- Grammar: `{{key}}`, `{{key|fallback}}`, `{{#if key}}..{{else}}..{{/if}}`, `{{#unless key}}..{{/unless}}`. No loops, no expressions. Every key must exist in `placeholders.json` (the build fails otherwise). Use `{{url.<doc>}}` for cross-links, never a literal path.
- Front matter on every document: `doc` (= file name), `title`, `version` (semver), `updated` (YYYY-MM-DD), `lang`, `summary`, optional `when: <key>` (publish only when that key is non-empty). Bump `version`/`updated` for every text change: MAJOR when rights or obligations change, MINOR for added clauses, PATCH for wording. Consumers must warn users on MAJOR/MINOR.
- Heading anchors `{#anchor}` are stable; other documents and translations rely on them.
- **Do not make section numbers depend on a flag.** Conditional content goes inside a numbered section or in its own document (`when:`). Hard-coded "section N" cross-references exist; if you renumber, grep for them in every language.
- A document published only for a flag must never be linked outside `{{#if flag}}` (the renderer reports `[url.x]` for links to unpublished documents).
- Keep the texts neutral about the company: no names, addresses, emails, registrations. Add a placeholder instead and document it in `placeholders.json`; keep the number of keys small (reuse, default with `@other.key`).
- Statements of fact about what the product does (MFA, deletion, deadlines) are promises the host must keep. If you add one, add it to the "Promises" list in the wrapper's AGENTS.md.
- Defaults marked `verify` (law, venue, limitation periods, retention) are starting points for counsel, not decisions.

## Translations

- Read `i18n/TRANSLATING.md` and `i18n/glossary.json`. A translation is faithful: no added, removed or merged clauses; the build rejects any change to tags, anchors, link targets, heading levels or table rows.
- New translations are always `status: draft` with `translation_of: <English version>`. **Never set `reviewed` or `reviewed_by`**: only a native-speaking lawyer does. Hosts hide drafts by default.
- When English changes, translations become stale (`translation_of` differs): the build warns. Re-translate or leave the warning.
- `sr-Cyrl` is generated by `src/Transliterator.php`; do not write it by hand. Add words to `EXCEPTIONS` or `i18n/keep-latin.txt` instead.
- Governing law, venue and authority per country and language are in `i18n/jurisdictions.json`, not in the texts.
- Add a language: create the directory, add the tag to `i18n/languages.json` (name, direction, fallback chain, aliases), extend the glossary first, write a `BRIEF-<lang>.md`, draft with the cheapest capable model, run the build, then request native review.

## Licences

- `licenses/texts/<id>.txt` are verbatim SPDX texts (copyright line templated as `{{license.year}} {{license.holder}}`). Do not paraphrase them. `LicenseRef-*` are our own and need counsel.
- Describe a licence only by tags that its text supports. Questions and rules are data in `licenses/advisor.json`; changing the advisor is a data change plus a fixture in `tests/fixtures/advisor.json`. The advisor is deterministic: do not add heuristics or AI.

## Implementation

- PHP >= 8.2, `declare(strict_types=1)`, PSR-4 `rapttor\legal\`, no runtime dependencies. The grammar and the advisor must stay specifiable by `tests/fixtures/*.json` so other-language ports can pass them; if you change behaviour, change the fixtures and SPEC.md in the same commit.
- Releases are git tags `vMAJOR.MINOR.PATCH` (SemVer; below 1.0 the texts are unreviewed). From 1.0 MAJOR = rights or obligations changed, MINOR = clauses added, PATCH = wording; each document also has its own semver in front matter. Wrappers require `^MAJOR.MINOR` and update with `composer update`. Update `CHANGELOG.md` for every release; see `docs/PUBLISHING.md`.
- Licences of this repo: code MIT (`LICENSE`), texts and data CC BY 4.0 (`LICENSE-TEXT`); third-party texts in `licenses/texts/` keep their own terms.
